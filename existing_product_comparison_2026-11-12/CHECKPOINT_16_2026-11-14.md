## 2. The 132 "CHECK field path" warnings

**Cause.** `02_build.py` `current()` looked for a destination only inside the record's `fields`. Its top-level lists (`open_questions`, `conflicts`) were therefore reported as "no such field in the template".

**Classification of all 132**, checked against the target tier file of each row:

| Destination | Rows | Verdict |
|---|---|---|
| `open_questions` with `propose_note` | 121 | valid; the list exists in the target tier file |
| `open_questions` with `propose_open_question_update` | 9 | valid |
| `conflicts` with `propose_citation_correction` (Nyfrost 32, page reference inside a conflict entry) | 1 | valid |
| `open_questions` with `propose_record_conflict` (RF6400, batch 2) | 1 | **invalid destination**: a conflict entry addressed to the open-question list |

Two rows with parenthesised paths ("(no template field) ...") are explicit labels and were never printed as warnings.

**Corrections.**
- **Build.** A record-level list (`open_questions`, `conflicts`, `source_documents`) of the target tier file is now reported as "top-level list (...), not a template field". "no such field in the template" is left only for a path that resolves nowhere. The warning also now covers "no tier N file". No production schema was changed, and the warnings were not suppressed wholesale: a genuinely invalid path still prints and fails.
- **RF6400.** The row was split in `gen_b2_richful.py`:
  - a conflict entry (`conflicts`, `propose_record_conflict`) recording the US 2022 / REACH 2023 SDS composition difference;
  - a separate `propose_open_question_update` narrowing "All shared values agree" to the physical values. Its citation was re-checked: section 9 of the US SDS is on pp.4-5.
  - No formulation change is inferred, and the classification questions stay open.

**Why 67/67 passed with these warnings.** The only check on destinations was "every field row names an existing product and a resolvable current field **or says none exists**". It rejected only "product not found", so it accepted "no such field" by design.

**New check 68** (with regression cases). Every destination must resolve to one of:
- a template field;
- a record-level list of the target tier file;
- an explicit "(no template field)" label.

In addition, no conflict entry may be proposed into `open_questions`.

**Result.** 0 "CHECK field path" warnings remain. 133 rows target record-level lists, including the new RF6400 row.
