## Interpretations used (need reviewer confirmation)

- **I-1.** A numeric requirement needs a point value or a two-sided range (min and max). A one-sided bound alone (e.g. "minimum 4.0") does not satisfy it, because a calculation cannot use it.
- **I-2.** CCS "vs temperature" is satisfied by at least one CCS value with its test temperature; the slide lists -15/-20/-25/-30 °C as the possible pairings, not as four required points.
- **I-3.** Component "primary and secondary function": the secondary function is optional (not every component has one); the primary function is required.
- **I-4.** Component function-specific marker: required only for the functions the slide names (detergent: TBN + Ca or Mg; ZDDP: P + Zn; molybdenum: Mo). For other functions the slide defines no marker, so the item does not apply (rule CG-6-APPL). If the function itself is missing, applicability cannot be established and the item is missing.
- **I-5.** Viscosity modifiers and pour point depressants must also meet their subtype block (slide 4: "VMs and PPDs stay components, but need response data on top"). The template numbering of vm.json (tier 2) and ppd.json (tier 3) is file numbering, not a statement that the blocks are optional. Subtype fields that sit in a non-VM general.json are ignored.
- **I-6.** A treat rate must be on a stated mass basis (wt.%, wt%, mass %). A bare "%" or "vol.%" does not establish the wt.% basis the slides require.
- **I-7.** A response (thickening, pour point, low temperature) is usable only with its reference oil, dose and test method (slide 4 rule); a calculated response also needs its inputs and arithmetic to check.
- **I-8.** Package "required VM / PPD / booster architecture" is satisfied by at least one reported co-component. The schema has no field for a sourced statement that none is required; such a statement would need a schema decision before it could satisfy the item.
