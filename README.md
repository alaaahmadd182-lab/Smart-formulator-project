# Smart Formulator – raw-material data preparation

Structured, source-traceable extraction of supplier datasheets (base oils, additive packages,
additive components) following `Smart_Formulator_Minimum_Property_Set.pdf`, which is inside
`Manual + Data to share.zip`.

| Path | Contents |
|---|---|
| `Property_Glossary.docx` | Task 1 – property glossary |
| `json_templates/` | Task 2 – one JSON template per material class and tier |
| `Products_json/` | Task 3 – one folder per product, one JSON file per tier |
| `build_coverage_matrix.py`, `Coverage_Matrix.xlsx` | Task 4 – coverage script and its output |
| `source_registry.json` | External (non-archive) sources cited in `Products_json`, with verification status |
| `Raw_Material_Missing_Properties_2026-10-13.xlsx` | Full raw-material inventory (453 materials) with missing-property status per material |
| `open_questions_and_conflicts.md` | Task 5 – conflicts and open questions |
| `reconciliation/` | Task 3 – reconciliation of the 453-material inventory with `Products_json`, ingestion queue, identity review and unverified research leads |

## Scope

| | Base oils | Additive packages | Additive components | Total |
|---|---|---|---|---|
| Full inventory (`Raw_Material_Missing_Properties_2026-10-13.xlsx`) | 202 | 130 | 121 | **453 materials** |
| Processed JSON subset (`Products_json/`, `Coverage_Matrix.xlsx`) | 181 | 77 | 3 | **261 JSON product folders** |
| Inventory materials represented by those folders | 180 | 77 | 3 | **260 materials** |
| Inventory materials not yet represented | 22 | 53 | 118 | **193 materials** |

The 261 product folders are stored in **701 JSON files**, because each product has one file per
tier (base oils: 3 tiers; additive packages: 2; additive components: one file per component
template, e.g. `general.json`, `vm.json`, `ppd.json`).

The 261 folders represent 260 inventory materials because one material, `BO-S-OIL-ULTRA-S-8`
(Ultra-S 8), currently maps to two folders: `S_OIL_ULTRA_S_8` and `S_OIL_ARAMCO_ULTRA_8` (the
aramcoULTRA 8 rebrand; see `reconciliation/identity_review.md`, ID-01).

The inventory is **not** fully ingested. Of the 193 materials without JSON
(`reconciliation/README.md`):

- **Category B (archived supplier datasheet): 0.** All nine were ingested.
- **Category C (mentioned only in other products' documents): 23.**
- **Category D (no archived source located): 170.**

The two workbooks cover different scopes and are not interchangeable:

- `Raw_Material_Missing_Properties_2026-10-13.xlsx` – the whole 453-material library as of
  2026-10-13: which Minimum-Property-Set items are present or missing for every material, with a
  document register. It is not generated from `Products_json`.
- `Coverage_Matrix.xlsx` – generated by `build_coverage_matrix.py` from the 261 processed product
  folders only: the status of every property in the JSON, validation findings and source traceability.
  Materials outside the processed subset do not appear in it.

## Building the coverage matrix (Task 4)

Requires Python 3.12 (Windows, macOS or Linux). From the project folder:

```
python -m pip install -r requirements.txt
python build_coverage_matrix.py --output Coverage_Matrix_new.xlsx
```

Options: `--input` (default `Products_json`), `--output` (default `Coverage_Matrix.xlsx`),
`--sources` (default `source_registry.json`) and `--overwrite`. Without `--overwrite`, the script
refuses to replace an existing workbook.

The script only reads the JSON files; it never changes them. The workbook contains:

- **Overview** – product, file and status counts, plus the run status.
- **Base Oils / Additive Packages / Additive Components** – one row per product, one column per
  property. Each cell is `reported`, `calculated`, `missing` or `not_applicable`.
- **Validation Issues** – structural problems, plus non-blocking review items: mixed nested
  statuses, a status that contradicts its value, a value outside its own min/max, and a KV40/KV100
  test temperature that differs from the property.
- **Status Detail** – every nested status in the JSON, with its original spelling, the source file and the page.
- **Traceability Audit** – the source of every reported value, its issuer type and issuer, with a severity:

| Finding | Severity |
|---|---|
| Reported value without source; basis `general_knowledge` | warning |
| Archive source without page reference | warning |
| External source not in source registry | warning |
| External source unreachable / unverified | warning |
| Verified independent third-party PDF or web page | warning |
| Verified manufacturer- or distributor-issued PDF without page reference | warning |
| Verified manufacturer-issued PDF with page; web page (no page numbers) | info |
| Verified distributor-issued PDF with page; web page (no page numbers) | info |

  A finding ending in `; archived copy` is a verified web-archive copy (e.g. a Wayback Machine
  snapshot) of the issuer's document. A verified distributor document is valid evidence, not a
  warning; the issuer is named so that it is not mistaken for the manufacturer.

### Source registry

`source_registry.json` lists every external URL cited in `Products_json`: publisher, host
(`manufacturer`, `distributor`, `archive` for a dated web-archive copy of a manufacturer document
that is no longer retrievable directly, or `third-party`), issuer (who issued the document:
`manufacturer`, `distributor` or `third-party` for a party independent of both) and `issued_by`
(the issuer's name), format (`pdf` or `html`), title, edition, status
(`verified`, `unreachable` or `unverified`), the date it was checked and, for PDFs, the SHA-256 of the
retrieved copy. Web pages have no page numbers, so a verified web page is not a warning. A URL must
be added to the registry, after its content has been checked, before it stops being reported as a
warning. The registry records that a source was checked; whether it supports each individual value
is recorded in that value's notes.

When a property has subfields with different statuses, the cell shows the highest-priority
status (reported > calculated > missing > not_applicable) and is shaded amber. **A cell marked
`reported` may still contain missing subfields**; Status Detail lists every subfield.

### Exit codes and failed validation

| Code | Meaning |
|---|---|
| 0 | Passed; workbook written |
| 1 | Usage error (input folder not found, or output exists without `--overwrite`) |
| 2 | Validation failed; `<output>_DIAGNOSTIC.xlsx` is written instead and the requested output is **not** touched |

Validation fails on any of the following: an unrecognized status value (shown in red as
`unrecognized: <value>`, never converted to `missing`), an unreadable file or invalid JSON, a
missing material class or record ID, a duplicate tier or property, a missing expected tier, or
data without any status.
