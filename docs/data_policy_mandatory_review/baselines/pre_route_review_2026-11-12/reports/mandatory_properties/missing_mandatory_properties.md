"Documented" (companion measure, `documentation_coverage.csv`) is NOT completeness: it counts products for which every mandatory requirement is met, is a valid range or bound (never replaced by a point), or has a pending source selection on an otherwise complete value. It is derived from the outcome category, so a value that has both a pending selection and incomplete metadata is counted by its metadata defect; the independent selection status is the column `selection_pending` of `requirement_outcomes.csv`. Evidence documentation, value selection, value form, percentage basis and verification status are reported as separate attributes by `python tools/mandatory_properties/build_readiness.py` (`property_attributes.csv`).

## Interpretations and approved policies in force

Entries marked "Approved policy" were approved on 2026-11-11; the others remain provisional.

- **I-1.** [Approved policy 1, 2026-11-11] Ranges, one-sided bounds and direction-less specification values are documented information. They are never converted to an exact value, never given an invented midpoint and never reported as absent. A requirement that needs a point value is not satisfied by them; a calculation may use them only if its registered method accepts that form (no range-aware method is registered).
- **I-2.** CCS "vs temperature" is satisfied by at least one CCS value with its test temperature.
- **I-3.** Component "primary and secondary function": the secondary function is optional; the primary is required.
- **I-4.** Function-specific markers are required for the functions the slide names (detergent: TBN + Ca or Mg; ZDDP: P + Zn; molybdenum: Mo). For other functions applicability is unresolved (not assumed inapplicable).
- **I-5.** VM and PPD subtype blocks are reported but not blocking, because they are stored in tier 2 / tier 3 files and the project rule says missing Tier 2/3 data does not block. This conflicts with slide 4 ("need response data on top") and is a decision for the reviewer (decision C).
- **I-6.** [Approved policy 3, 2026-11-11] The basis of a percentage is mass, volume or unspecified. It is established from the recorded unit or from reviewed source evidence (heading, footnote or explicit document-wide convention) in treat_rate_basis_evidence.json. An unspecified "%" stays unspecified, and a volume percentage stays volume: neither satisfies a wt.% requirement. No volume-to-mass conversion is registered or used; volume evidence is listed separately and never fills a wt.% field.
- **I-7.** A response is usable only with its reference oil, dose and method (glossary extraction rule). A calculated value is accepted only if a registered check reproduces it from inputs printed on the cited page and its conditions match the response record.
- **I-8.** [Approved policy 2, 2026-11-11] Package co-components are assessed per evidenced route. A route is complete only if every requirement that applies to it has a usable mass-basis dose and its requirement list is confirmed by source review; one usable component never completes a route that needs others, and routes are independent. Without reviewed route evidence the association is unresolved and completeness is not assessed. The product-level requirement is met only by a complete evidenced route or by an explicit, unqualified, applicable statement that none is required. An empty record is "not recorded", never supplier silence.
- **I-9.** [Approved policy 4, 2026-11-11] A Not Required / Not Applicable label satisfies a requirement only under a rule approved for the product class, the requirement and the task. No rule is approved. A Missing value or an unsuccessful search is never treated as not applicable, and no property changes tier.
